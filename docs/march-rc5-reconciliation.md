# March rc5 Build Reconciliation

This document compares three sources:

1. March rc5 build script: `_reference-march-rc5-build/scripts-final/PODKOP+AmneziaWG_openwrt_v25_FULL (LATEST 23Feb).sh`
2. March firmware manifest: `_reference-march-rc5-build/firmware-bcm2711-current/bcm2711/openwrt-bcm27xx-bcm2711-rpi-4.manifest`
3. Current production router snapshot: `_reference-current-router/20260528-030422`

The conclusion is clear: the March script is a strong base, but the running router is now ahead of it operationally. The new build should not be generated by blindly rerunning the March script.

## Baseline

| Area | March rc5 script | Current router | New build decision |
|---|---|---|---|
| OpenWrt base | `v25.12.0-rc5` | `25.12.0-rc5` | update to latest stable, currently `25.12.4` |
| Kernel | `6.12.71` | `6.12.71` | use kernel from selected stable release |
| Target | `bcm27xx/bcm2711` | `bcm27xx/bcm2711` | preserve target unless CM5 support requires profile split |
| Boot partition | `128` MB | `128` MB | preserve |
| Root partition | `2048` MB | `2048` MB | preserve |
| Package manager | APK-era OpenWrt | APK | preserve APK workflow |

## Things The March Script Already Covers Well

These should be carried forward into the new build system:

- custom Realtek `r8168 8.056.02` RSS/multi-queue package
- `r8169` conflict avoidance through custom `kmod-r8168-8.056.02-rss`
- AmneziaWG kernel/userspace/LuCI integration
- Podkop feed integration and `sing-box` full package preference
- NateLol OLED feed/package fixes
- boot config for I2C, overclock, GPU memory minimization, and noaudio overlay
- `/etc/config/oled` defaults
- `/etc/init.d/oled-i2c-fix`
- `cpu-governor` init script
- BBR/sysctl network buffer tuning
- `network.globals.packet_steering=2`
- target root/boot partition sizes
- `CONFIG_HZ_1000=y` / `CONFIG_HZ=1000` in the build config

## Things The Live Router Adds After March

These need to be incorporated deliberately:

| Live-router item | Why it matters | New build handling |
|---|---|---|
| `bash` | required by current `cake-autorate` install | include if shipping autorate |
| `fping` | required by autorate and health checks | include |
| `tcpdump` + `libpcap1` | repeatedly needed for real diagnostics | include |
| `cake-autorate` service | dynamic SQM rate adjustment | package or scripted install/template |
| `awg2-health-monitor` | observes DNS/tunnel health and VPS shaper state | optional advanced overlay/template |
| `awg2-shaper-publisher` | sends router-derived rate to VPS AWG2 shaper | optional advanced overlay/template |
| `chronyd` enabled, `sysntpd` disabled | production time model | make chrony the default time service |
| `/etc/sysctl.d/99-wan-hardening.conf` | disables WAN redirects/source routing and IPv6 WAN behavior | include as board/profile hardening |
| `/etc/sysctl.d/10-disable-ipv6.conf` | global IPv6 disable for this deployment style | include only in full-vpn profile or document clearly |
| `/etc/sysctl.d/11-conntrack-timeouts.conf` | long-lived connection tuning | evaluate and likely include |
| Technitium DNS route to `10.8.1.254` | production-specific DNS architecture | document/template, do not hardcode into public default |
| Port forwards to Synology services | production-specific | do not include public firmware defaults |
| personal Podkop domain lists | private operational policy | do not publish defaults; use examples only |

The Podkop difference confirms the March image manifest is stale relative to the post-build/manual package correction. The new build must make Podkop versioning deterministic and must not reproduce the date-version fallback problem.

## OLED Reconciliation

March script assumes OLED `START=100` for the fixed behavior. Production router currently has `START=1OO` in `/etc/init.d/oled`.

Decision:

- keep the same OLED package and I2C fix behavior;
- fix the typo to `START=100` in the new image;
- test on spare board before treating it as production-safe.

## Build Profile Impact

### Performance Profile

Must include:

- board boot config
- r8168 custom driver
- OLED + LuCI
- CPU governor
- BBR/sysctl tuning
- packet steering
- chrony + LuCI
- SQM + LuCI
- irqbalance + LuCI
- practical diagnostics: `fping`, `tcpdump`, `bind-dig`, `curl`, `jq-full`, `btop`, `nload`, plus the additional target tools listed in `docs/packages.md`

### Full VPN Profile

Must include everything in performance plus:

- AmneziaWG kernel/userspace/LuCI
- Podkop + LuCI
- full `sing-box`
- DNS/routing helpers needed by Podkop
- optional templates for Technitium tunnel-local DNS and AWG2/VPS shaper integration

## Do Not Publish As Defaults

These are useful for the private network but should not become public firmware defaults:

- AWG private/public/preshared keys
- production VPS endpoint values
- shaper SSH private key
- Synology/Plex/TheSecretary/torrent/Homey port forwards
- personal DHCP reservations
- personal Podkop domain lists
- production Technitium-specific IP unless documented as an example
